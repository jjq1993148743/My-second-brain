# 浏览器自动化方案候选（待试验）

> 用途：让 AI 复用我已登录的浏览器，帮我搜商品、看评论。核心约束：**账号和 IP 不能封**（见 [[AGENTS]] §0.1）。
> 结论：**第一梯队装 Tencent/BrowserSkill**，第二梯队作备选。
> 信息时效：**截至 2026-09**。数据来源：GitHub API 实测 + 知乎 / CSDN / 掘金 / 博客园 / skills.sh。

## 判断依据：路线和形态是两件事

| 概念 | 决定什么 |
|---|---|
| **技术路线** | 反爬能力（会不会被识别） |
| **交付形态** | 好不好用（Agent 能不能驱动它） |

| 路线 | 反爬 | 说明 |
|---|---|---|
| **扩展注入** | ★★★★★ | 复用真实浏览器会话，无需伪装 |
| CDP 直连 | ★★★ | 指纹真实，但 CDP 连接可被检测；Chrome 136+ 默认 profile 受限 |
| 模拟点击 | ★★ | `navigator.webdriver=true` 一行暴露 |

> **反爬评级取决于路线，不取决于形态。** 纯扩展和「CLI + 扩展」只要都是扩展注入，反爬一样好。
> 但对「AI 帮我操作」这个场景，**形态是决定性的**：纯扩展活在浏览器里，外部 Agent 够不着。

## 第一梯队 · 装这个

| 方案 | 理由 |
|---|---|
| **Tencent/BrowserSkill** | 腾讯官方 + 扩展注入（反爬最好）+ 复用真实登录态 + 独立窗口可接管 + 官方适配 WorkBuddy + Windows x64 支持 + 无需写代码 |

- 仓库：https://github.com/Tencent/BrowserSkill
- 架构：`bsk` CLI（Rust，含后台 daemon）+ 浏览器扩展 + Skill
- 实测（2026-09-28）：**7,517 stars**｜MIT｜最后推送 2026-09-27｜open issues 56
- 关键特性：任务跑在独立的「Agent Window」（橙色高亮），用户标签页默认只读、需显式借用；遇验证码/支付/二次验证会暂停并请求人工介入
- 安装三件套：CLI（PowerShell 脚本）→ Chrome/Edge 扩展 → `bsk install-skill`

## 第二梯队 · 备选或搭配

| 方案 | 什么时候用 | 代价 |
|---|---|---|
| **remorses/playwriter** | 想省 token（全项目只有 1 个 `execute` 工具）、要精细受控范围（受控 tab 变绿） | 要写 JS、没有独立窗口、个人维护 |
| **nanobrowser** | 想零命令行，装个扩展就用（13,833 stars） | 要自配 LLM API key、纯扩展形态能力弱 |
| **chrome-devtools-mcp** | **只在排查网页问题时用**（性能 Trace / Console / Network / 无障碍审计） | 吃 token、Chrome 136+ 连已有 Chrome 受限 |

## 不推荐

| 方案 | 原因 |
|---|---|
| hangwin/mcp-chrome | 12.5k stars 但**8 个月未更新**，231 个 issue 积压 |
| browser-use | 是「AI 自主规划」框架，慢（每步 2–5s）、贵、可靠性 72–78%，不是按指令执行的工具 |
| playwright-mcp | 启动独立浏览器，**带不进登录态** |
| microsoft/playwright | 是引擎不是成品，要自己写代码 |
| 各类「反检测」项目 | 设计目的是规避平台检测 |

## 关键事实（AI 核实，非我原话）

> 以下为 AI 整理时补充，标注来源与置信度。

1. **Chrome 的 `--remote-debugging-port` 自 Chrome 136 起在默认 profile 上被忽略** —— 必须改用一次性 `--user-data-dir`（里面没有登录态）。来源：playwriter 官方文档。旁证：本机 `web-access` skill 要求在 `chrome://inspect/#remote-debugging` 勾选显式授权。**推论：CDP 直连路线在现代 Chrome 上基本失效。**
2. **skills.sh 上 browser 类 skill 以 CDP 路线为主** —— `agent-browser`（vercel-labs）36,434 安装排第一；**全站唯一走扩展注入路线的 `cdp-bridge` 只有 13 个安装**。
3. **skills.sh 上的 skill 是「操作说明书」不是「工具本体」** —— `agent-browser` skill 只教 Agent 怎么用 agent-browser CLI，不改变底层路线。
4. **腾讯 BrowserSkill 自带 skill**（`bsk install-skill`），不需要从 skills.sh 装。
5. 社区共识（博客园 / CSDN）：**扩展注入是唯一经得起生产环境考验的方案**，因为它不需要伪装。
