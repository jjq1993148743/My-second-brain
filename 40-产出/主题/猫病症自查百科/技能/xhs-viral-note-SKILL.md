## 3.5 长尾词埋设（**每篇必做，漏了等于白写**）

底表每条的「其他叫法」列（通用叫法 / 老话方言 / 网上说法）**就是现成的搜索词库**，必须全部用上。

### 三个位置，各管一段搜索流量

| 位置 | 放什么 | 作用 |
|---|---|---|
| **标题** | 1–2 个最高频的主词 | 平台主要靠标题分词 |
| **标签** | **补满 10 个**（平台上限） | 搜索匹配 |
| **正文** | 俗称 / 老话 / 网上说法，**自然嵌 2 处** | 让算法判定「标签与内容相关」 |

**只堆标签、正文不出现 → 算法判定标签与内容不符，反而降权。** 必须两头都埋。

### 正文埋词的两个位置

```
开头（第 1–2 段）：把俗称自然引出来
    "那时候我还不知道「乱尿」「频繁上厕所」「尿团变小」这些词指的是同一件事。"
结尾（正文倒数第 2 段）：把老话/方言作为总结
    "尿淋、热尿、滴尿、粉色猫砂 —— 这些说法我一开始都没对上号。"
```

### 标签配比（10 个）

| 类型 | 数量 | 例（尿血） |
|---|---|---|
| 主症状词 | 2 | #猫尿血 #猫尿床 |
| 俗称 / 口语 | 3 | #猫乱尿 #猫尿闭 #猫咪尿频 |
| 病名 / 专业 | 2 | #猫咪膀胱炎 #猫下泌尿道 |
| 人群 / 场景 | 1 | #猫咪应激 |
| 泛流量词 | 2 | #科学养猫 #养猫新手 |

**忌**：10 个全是泛词（#科学养猫 ×10 那种），等于没做关键词。

### 交付前自检

- [ ] 标签数 = 10（不是 5，不是 8）
- [ ] 底表「其他叫法」三栏的词，至少在正文出现 3 个
- [ ] 标题里出现的症状词，和标签不重复堆砌

## 4. 正文结构（见证型，8 段）

爆款的核心是**「我试过、成了」**，不是科普。按这个顺序写：

```
1. 开局困境    —— 一个具体动作（"铲起来的那一下我就知道不对"）
2. 误判        —— 我没当回事 / 网上都说 X
3. 时间推移    —— 结果一拖就是 N 天
4. 转折点      —— 第 N 天我做了个决定：……
5. 中间结果    —— 第 N 天，开始变化
6. 结局        —— 没吃药，没去医院，就是 X 了
7. 图导览      —— 往下翻，第一张……第二张……
8. 安全边界    —— 说这些不是让你别去医院（见 §6）
```

**结尾必须有三件套（2026-11-15 用户要求）**：

```
① 讨论钩子 —— 抛一个二选一或让人想报答案的问题
② 关注理由 —— 给出「关注能得到什么」的具体承诺
③ 共同体感 —— "我们一起来养猫"这类邀请语
```

**结尾模板（按症状替换方括号）**：

```
你家猫是第几种？[具体选项A] 还是 [具体选项B]，评论区报个数，我按形态归类回复。

一共 72 条，我一条条写。想看哪条，评论区点单。

关注我，看我怎么把这 7 只的每一个坑都记录成能用的自查表——我们一起来养猫。
```

## 5. 6 图结构（单篇）

| # | 图 | 内容 | 对应爆款手法 |
|---|---|---|---|
| 1 | **封面** | 主角真猫照片 + 粗描边大字标题 + 形态对照 | 「便便7种状态」2.40x 收藏率 |
| 2 | **分级/时间线** | 拖到第几天该怎么处理 | 「居家治疗总结」6,410 赞 |
| 3 | **对照表** | A 情况 vs B 情况，6 行分清 | 「六行就能分清楚」认知冲突 |
| 4 | **自测清单** | 在家能做的 N 个动作 + **真实照片** | 差异化：主人动作颗粒度 |
| 5 | **执行方案** | 停什么 / 做什么 两栏 | 「居家」高频词 |
| 6 | **经验清单** | 9 条踩坑，没有一条让你买东西 | 收藏钩子 |

**视觉规范（对标爆款，不是极简风）**：
- 标题用**粗描边大字**（`-webkit-text-stroke: 14-16px` + `paint-order: stroke fill`）
- 高饱和配色：红 `#ff3b30`、黄 `#ffd60a`、绿 `#2e9e5b`
- 封面必须有**真实照片**，不能纯矢量
- 三色语义固定：绿=可观察 / 黄=要留意 / 红=当天就医

## 6. 安全边界（强制，不可省）

**凡写「没去医院/在家好了」，必须紧跟一段边界声明**，否则会误导读者延误就医：

```
说这些不是让你别去医院。第 3 种（[危险特征]）拖过两周的，最多的原因是 [真实病因]，不是 [表面原因]，这条必须送检。我是第 N 种，[良性特征]，才敢在家试。
```

**同时**：
- 正文必带「症状不等于诊断，最终由兽医排查」
- 涉及用药 → 一律「凭医院处方」，不给剂量
- 文末带 AI 声明

### 7.1 AI 生图能补什么、不能补什么（2026-11-16 实测定稿）

> 模型横评与完整规则见 `70-Skills/free-text-to-image/SKILL.md` §小红书配图专用。
> 这里只写**做 6 图时怎么用**。

| 图位 | 用什么 | 理由 |
|---|---|---|
| **1 封面** | **必须用户真猫照片** | §5 L157 硬规则；AI 猫老用户一眼看出，封面垮了整篇垮 |
| 2 分级/时间线 | **不用图**，纯 HTML 排版 | 数字和文字 AI 出不了 |
| 3 对照表 | **底图可 AI**（Z-Image-Turbo 能按顺序摆多主体）+ 后期加标注 | 比实拍拼图快；**别用智谱**，多主体并列会跑偏 |
| 4 自测清单 | 用户真猫照片（动作照） | 「主人动作颗粒度」是差异化点，必须真实 |
| 5 执行方案 | 环境/道具可 AI（猫砂盆、猫碗、药品静物、猫爬架） | 实拍里没有这些干净素材，AI 出图可控 |
| 6 经验清单 | 不用图 | 纯文字 |

**AI 生图统一参数**：

```
尺寸：1242×1656（3:4）—— 所有上游都直接支持，别要 2484×3312
模型：默认 qwen_generate_image（远程网关，width=1248 height=1664）
      要极致画质 → bridge modelscope（Qwen-Image-2.1）
      要快/批量 → bridge modelscope_fast（Z-Image-Turbo，8.8s/张）
prompt 开头：写实摄影
prompt 结尾：画面无文字无水印
```

**三类绝对不要用 AI**：
1. 任何文字/数字（标题字、24/48/72 小时刻度）→ 乱码
2. 封面主角 → 见上
3. 症状特写（呕吐物、便便）→ 用 `素材库/啤酒/` 的 beer-03/04/05/14/16/17/18/20，实拍可信度高得多

**已淘汰的模型**（别用，中文 prompt 会出完全无关的图）：Cloudflare flux-1-schnell、Pollinations flux。


## 8.5 交付形态：发布稿文件夹（**每篇必做**）

做完 7 图之后，**不要只丢一堆 PNG**。生成一个「待发布」文件夹，用户拿着就能发。

### 文件夹结构

```
桌面\【待发布】第N篇-{症状}\
  ├─ 发布稿.html                    ← 手机打开，一键复制
  ├─ 发布文案.md                    ← 纯文本备份
  └─ 图片（按1到7顺序上传）\
       ├─ 1-封面.png
       ├─ 2-xxx.png
       └─ ...（文件名带序号，按名排序即上传顺序）
```

### 发布稿.html 必须包含 8 个区块

| # | 区块 | 要求 |
|---|---|---|
| 01 | 标题 | 可复制块 + 字数提示 |
| 02 | 正文 | 可复制块（**max-height 限高 + 滚动**，别撑爆手机） |
| 03 | 标签 | 可复制块 + 「确认变蓝」提示 |
| 04 | 表单勾选 | 表格：定时 / 合集 / AI 声明 / 原创 / 地点 / 可见范围 |
| 05 | 图片顺序对照 | 序号 + 内容 + 文件名，上传时核对 |
| 06 | 发布后 2h 自查 | 曝光低于均值 20% → 查同质化/AI 味/敏感词 |
| 07 | 数据依据 | 赛道最高赞、收藏率、底表序号、文献 |
| 08 | 与前篇差异化 | 主色 / 封面形态 / 钩子类型对比，防判同质 |

### 一键复制的实现

```javascript
function cp(id, btn){
  var txt = document.getElementById(id).innerText;
  var done = function(){ /* 按钮变「✓ 已复制」1.8s 后复原 */ };
  if (navigator.clipboard) {
    navigator.clipboard.writeText(txt).then(done).catch(function(){ fallback(txt,done); });
  } else { fallback(txt, done); }
}
function fallback(txt, done){
  var ta = document.createElement('textarea');
  ta.value = txt; ta.style.position='fixed'; ta.style.opacity='0';
  document.body.appendChild(ta); ta.select();
  try { document.execCommand('copy'); done(); } catch(e){ alert('请手动长按'); }
  document.body.removeChild(ta);
}
```

**必须做降级**：`file://` 协议下 `navigator.clipboard` 在部分浏览器被禁用。

### 三条硬规矩

1. **不代发**。生成文件夹交给用户，AI 不接触登录态。发帖是写入操作，自动化指征（点击间隔/鼠标轨迹/输入速度）与真人不同，一旦被判风控，损失远大于省下的几分钟。
2. **标题/正文/标签各自独立成块**，不要合并成一大段——用户要分开粘到三个输入框。
3. **AI 声明那句必须在正文里**（「（本内容为 AI 辅助整理…）」），这是平台要求的可见标识，光勾选发布页的框不够。

## 10. 踩过的坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 相对路径图片 | headless 截图空白 | HTML 内嵌 base64 |
| HTML 太大 | 手机打开白屏 | 图压到长边 1400、质量 82，总量 <1.5MB |
| headless 最小宽度 | `--window-size=375` 无效果，实际 762px | 用 CDP `Emulation.setDeviceMetricsOverride` 验证 |
| flex `justify-content:center` 加在列表上 | 内容挤中间，上下大空白 | 加在 body 上，列表用 `gap` 控制间距 |
| 裁图鉴时文字混进来 | 图里带原标注 | 用连通域分析（scipy）只取图形，或直接换整图 |
| 标题想塞太多信息 | 全部超 20 字 | **压到 13-16 字反而更狠** |
