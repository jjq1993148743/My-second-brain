# 小红书爆款笔记生产（数据驱动版）

> v1.0.0（2026-11-15）。基于 323 条真实赛道的逆向工程。
> 与 `xhs-cat-symptom-SKILL.md`（两期 11 图版）的区别：**这个版本先看数据再写，单篇打透，标题优先**。
> 定稿实例见 `成果物/06-软便-爆款版/`；数据依据见 `调研/爆款标题拆解-323条实测.md`。

## 0. 硬约束（先背下来）

| 项 | 值 | 依据 |
|---|---|---|
| 标题字数 | **≤20 字**（贴着写，别超） | 平台硬上限 |
| 画布 | **1242×1656（3:4）**，@2x 输出 2484×3312 | 与旧 SKILL 一致 |
| 图数 | **单篇 6 图**（不拆期） | 赛道 Top20 无一拆期 |
| 底色 | 暖白 `#faf9f7` ~ `#fff8e8` | 爆款封面均非纯白 |

## 1. 第一步永远是查数据（禁止凭感觉写标题）

**任何标题在写之前，必须先跑一遍赛道数据。**

```bash
cd D:/GitHub/XiaohongshuSkills
.venv/Scripts/python.exe scripts/xhs_analyze.py "关键词1" "关键词2"
.venv/Scripts/python.exe scripts/xhs_deep.py      # 结构分析
.venv/Scripts/python.exe scripts/xhs_title_re.py  # 标题逆向
```

**采集纪律（红线，违反即停）**：
- 串行，禁并发；请求间隔 3–10 秒随机
- 每关键词最多翻 3 屏；单次任务 ≤4 个关键词
- 出现验证码 / 429 / 403 / 要求登录 → **立刻停**
- **只用小号采集**，大号绝不登录用于分析

## 4. 正文结构（见证型，8 段）

爆款的核心是**「我试过、成了」**，不是科普。按这个顺序写：

```
1. 开局困境    —— 一个具体动作（"铲起来的那一下我就知道不对"）
2. 误判        —— 我没当回事 / 网上都说 X
3. 时间推移    —— 结果一拖就是 N 天
4. 转折点      —— 第 N 天我做了个决定：……
5. 中间结果    —— 第 N 天，开始变化
6. 结局        —— 没吃药，没去医院，就是 X 了
7. 图导览      —— 往下翻，第一张……第二张……
8. 安全边界    —— 说这些不是让你别去医院（见 §6）
```

**结尾必须有三件套（2026-11-15 用户要求）**：

```
① 讨论钩子 —— 抛一个二选一或让人想报答案的问题
② 关注理由 —— 给出「关注能得到什么」的具体承诺
③ 共同体感 —— "我们一起来养猫"这类邀请语
```

**结尾模板（按症状替换方括号）**：

```
你家猫是第几种？[具体选项A] 还是 [具体选项B]，评论区报个数，我按形态归类回复。

一共 72 条，我一条条写。想看哪条，评论区点单。

关注我，看我怎么把这 7 只的每一个坑都记录成能用的自查表——我们一起来养猫。
```

## 5. 6 图结构（单篇）

| # | 图 | 内容 | 对应爆款手法 |
|---|---|---|---|
| 1 | **封面** | 主角真猫照片 + 粗描边大字标题 + 形态对照 | 「便便7种状态」2.40x 收藏率 |
| 2 | **分级/时间线** | 拖到第几天该怎么处理 | 「居家治疗总结」6,410 赞 |
| 3 | **对照表** | A 情况 vs B 情况，6 行分清 | 「六行就能分清楚」认知冲突 |
| 4 | **自测清单** | 在家能做的 N 个动作 + **真实照片** | 差异化：主人动作颗粒度 |
| 5 | **执行方案** | 停什么 / 做什么 两栏 | 「居家」高频词 |
| 6 | **经验清单** | 9 条踩坑，没有一条让你买东西 | 收藏钩子 |

**视觉规范（对标爆款，不是极简风）**：
- 标题用**粗描边大字**（`-webkit-text-stroke: 14-16px` + `paint-order: stroke fill`）
- 高饱和配色：红 `#ff3b30`、黄 `#ffd60a`、绿 `#2e9e5b`
- 封面必须有**真实照片**，不能纯矢量
- 三色语义固定：绿=可观察 / 黄=要留意 / 红=当天就医

## 6. 安全边界（强制，不可省）

**凡写「没去医院/在家好了」，必须紧跟一段边界声明**，否则会误导读者延误就医：

```
说这些不是让你别去医院。第 3 种（[危险特征]）拖过两周的，最多的原因是 [真实病因]，不是 [表面原因]，这条必须送检。我是第 N 种，[良性特征]，才敢在家试。
```

**同时**：
- 正文必带「症状不等于诊断，最终由兽医排查」
- 涉及用药 → 一律「凭医院处方」，不给剂量
- 文末带 AI 声明

## 7. 素材来源规则（版权红线）

| 来源 | 能否用 | 条件 |

| **用户自己的照片** | ✅ 首选 | 存到 `素材库/{猫名}/` |

**用户照片处理流程**：
1. 原图 → `素材库/{猫名}/`，按 `beer-01.jpg` 编号
2. 写 `README.md` 索引，标注每张内容和可用性
3. 使用时裁剪到目标比例，**别拉变形**

## 8. 生产流程（一次做完）

```
1. 查数据      —— 跑 xhs_analyze / xhs_deep / xhs_title_re
2. 定标题      —— 按 §2 §3 生成 ≥10 个候选，跑字数筛选，留 ≤20 字的
3. 查素材      —— 素材库里有用户照片吗？没有就问用户拍
4. 写正文骨架  —— §4 八段结构，结尾三件套
5. 做 6 图     —— §5 结构，写自包含 HTML → headless 截图
6. 看图复核    —— 每张 read_image 检查：溢出/孤字/换行/留白过大
7. 打包        —— 单文件 HTML（内嵌 base64，长边压到 1400）
8. 交付        —— 桌面放 HTML + 6 张 PNG
9. push        —— 没推 = 没做
```

## 10. 踩过的坑

| 坑 | 现象 | 解法 |
|---|---|---|
| 相对路径图片 | headless 截图空白 | HTML 内嵌 base64 |
| HTML 太大 | 手机打开白屏 | 图压到长边 1400、质量 82，总量 <1.5MB |
| headless 最小宽度 | `--window-size=375` 无效果，实际 762px | 用 CDP `Emulation.setDeviceMetricsOverride` 验证 |
| flex `justify-content:center` 加在列表上 | 内容挤中间，上下大空白 | 加在 body 上，列表用 `gap` 控制间距 |
| 裁图鉴时文字混进来 | 图里带原标注 | 用连通域分析（scipy）只取图形，或直接换整图 |
| 标题想塞太多信息 | 全部超 20 字 | **压到 13-16 字反而更狠** |
