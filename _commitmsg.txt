DSH插件API修复：对照真实插件源码发现工具注册API全错（ctx.tool应为ctx.tools.register+defineTool），6个插件全部重写并用mock包实测6/6通过

对照真实插件dsh-plugin-mall源码后发现第三个致命bug：工具注册API完全错了。

真实API从dsh-plugin-mall源码提取：import defineTool from @deepseek-ai/dsh-tools，export function apply(ctx) 里用 ctx.tools.register(defineTool({name, description, parameters, output: {schema, render}, async execute(args, exec), presentCall}))。

我们之前的写法错误三个关键差异：注册方式我们写ctx.tool(name, def)真实是ctx.tools.register(defineTool(def))、参数格式我们写JSON Schema（type: object加properties）真实是扁平对象直接列参数名、必填标记我们写required数组真实是每个参数内required: true、输出我们直接返回真实是output: {schema, render}、execute参数我们只args真实是(args, exec)其中exec有signal。

重写后的插件结构：import defineTool、核心逻辑函数不变、export const name = 包名、export const inject = [tools]、export function apply(ctx)里ctx.tools.register(defineTool({name, description, parameters扁平对象, output: {schema: {type: string}, render}, async execute(args)返回内容})、export default {name, inject, apply}。

补充package.json字段：peerDependencies声明@deepseek-ai/dsh-tools为星号、peerDependenciesMeta标记optional true。为什么用peerDependencies：真实插件就是这么声明的（dsh-plugin-mall的peerDependencies有4个@deepseek-ai包）、由DSH宿主提供本地不需要装、标记optional避免安装警告。

验证方法：建一个mock的@deepseek-ai/dsh-tools（只实现defineTool等于def）、实际import插件调用apply(ctx)、检查注册的工具结构加实际调用execute。验证结果6/6通过：销售sales_script一致true execute true render true调用true长度4096、HR hr_toolkit 3605、律师legal_toolkit 3793、教师teacher_toolkit 3782、财务finance_toolkit 3681、运营ops_toolkit 3739。完整验证内容9项：export name是包名、export inject是数组、export apply是函数、ctx.tools.register被调用、工具name正确、有parameters、有output.render、execute返回字符串、实际内容3-4K字符。
