# 本机抓取通道全景（换电脑先读这一篇）

> 2026-10-18 实测。**这篇是整个「挣钱的道」情报体系的基建**——所有调研都从这些通道出。
> 换电脑 / 换环境后，先按本文把通道打通，再跑情报。顺序不能反。

## 一句话结论

**本机有 4 条抓取通道，1 条搜索通道。** 排序：**Chrome headless > 本机代理 > 搜狗微信检索 > 无**。
之前以为「网站被墙/被 Cloudflare 挡」，真相是**我们的 Node 脚本 TLS 指纹被识破**，换真实浏览器就通了。

## 一、四条抓取通道

| # | 通道 | 怎么用 | 状态 | 适用 |
|---|---|---|---|---|
| 1 | **Chrome headless** | `node chrome-fetch.mjs <url> [outfile] [waitms]` | ✅ **最强，主力** | Cloudflare 403 的站（Etsy/Upwork/PH/Envato/Patreon/NexusMods/Fiverr/Dcard/LINUX DO/知乎/贴吧/小红书…） |
| 2 | **本机代理 + Node http** | `node proxy-fetch.mjs` 里的 `get(url)` | ✅ 稳定 | 普通站、JSON Feed、API（V2EX/52pojie/豆瓣/B站/Gumroad/coconala…） |
| 3 | **搜狗微信检索** | `node sogou.mjs "查询词" [页数]` | ✅ **唯一搜索通道** | 搜中文赚钱信息、找信源 |
| 4 | ~~web_fetch / web_search~~ | — | ❌ **双废** | `web_fetch` 被 DNS 假 IP 挡（`fetch failed`）；`web_search` 无 DEEPSEEK_API_KEY |

## 二、关键技术细节（踩过的坑）

### 1. EADDRINUSE 是自己造成的，不是 VPN 坏了

第一次批量抓海外站时全报 `connect EADDRINUSE 127.0.0.1:7897`，误判成 VPN 故障。
**真相**：`proxy-fetch.mjs` 每个请求新建一个 socket 不关闭，几十次就把临时端口耗尽了。
**修法**：`new http.Agent({ keepAlive: true, maxSockets: 4 })` 复用连接。修完全部恢复。

### 2. 403 不是墙，是 TLS 指纹

Etsy / Upwork / ProductHunt / Envato / Patreon / NexusMods / Fiverr / Dcard / LINUX DO / 知乎 / 贴吧，走 Node `http.get` 全 403。
**换 Chrome headless 后大部分能通**（Reddit 实测拿到 190KB 真实 DOM）。
Cloudflare 认的是浏览器 TLS 栈，不是 IP。开 VPN 对这些站**没用**。

### 3. GBK 站点必须手动解码

52pojie 等 Discuz 老站是 GBK。Node 22+ 内置 `new TextDecoder('gbk').decode(buf)`，不用装 iconv-lite。

### 4. PowerShell 5.1 会吃字符（这是工具链最大坑）

用 PowerShell here-string 或字符串拼接往脚本里写 `\s`、`$`、反引号，**会被静默改写**，导致 Node 报
`Invalid regular expression flags` 或 `Unexpected end of input`。
**正确做法**：
- 脚本内容用 `tools.write()` 直接写文件，**不要经过 PowerShell**
- 或用 base64：写 `.b64` 文件 → `node -e "fs.writeFileSync('x.mjs', Buffer.from(fs.readFileSync('x.b64','utf8').trim(),'base64').toString('utf8'))"`
- 或直接在 `run_code` 里 `await import()` 内联跑

### 5. pwsh 工具超时会改变返回结构（我这次翻车的直接原因）

`pwsh({ command, timeoutMs: N })` **超过 N 毫秒后返回 `{ kind: 'promoted', jobId, output }`，没有 `stdout` 字段**。
代码里写 `res.stdout.text` 立刻 `Cannot read properties of undefined`。
**正确做法**：耗时命令要么不设 `timeoutMs`，要么 `run_in_background: true` 拿 jobId 再用 `job_output` 收。
**看到这个报错，先查是不是超时，别怀疑环境坏了。**

### 6. 持久终端会话回显会污染

`terminal_send` 在这个环境会把命令字符一个个插进回显，读回来的内容不可用。
**别用 terminal 跑需要看输出的命令**，用 `run_code` 内联或后台 job。
