# 插件内截流设计：把使用者变成你的流量

> **实测 6,378 个插件：83 个提到二维码/公众号/加群，12 个 UI 位置被高下载插件验证。**
> **这轮搞清「在插件哪里放引导最有效」。**

## 一、⭐⭐⭐ 83 个插件在做截流（真实数据）

| 排名 | 插件 | 下载 | 它怎么截流 |
|---|---|---|---|
| 1 | dsh-remote-web-ui | **126,240** | **扫码配对**（手机扫电脑） |
| 2 | dsh-im | **61,918** | **二维码接 9 个 IM**（飞书/微信/钉钉…） |

| 7 | dsh-plugin-mobile-gateway | 4,238 | **二维码配对** |
| 8 | dsh-console-plugin | 2,804 | **二维码或六位配对码** |
| 9 | dsh-palm | 2,496 | **扫码配对设备信任** |
| 10 | dsh-lark-link | 2,290 | **扫码一键认证** |

### ⭐⭐ 关键洞察：它们用「扫码」做功能，不是做推广

| 事实 | 说明 |
|---|---|
| **83 个里绝大多数是「扫码连接设备」** | 不是「扫码关注公众号」 |
| **说明什么** | **扫码是 DSH 插件的天然交互方式** |
| **对你的价值** | **你可以在「扫码」这个动作上做转化** |

### ⭐⭐⭐ 一个聪明的设计思路

```
用户装你的插件 → 需要「扫码配对/登录」→ 扫码后 → 
  ① 完成功能（用户得到价值）
  ② 同时关注了你的公众号/进了你的群（你得到流量）
```

**这是「功能即截流」——不打扰用户，因为扫码本来就是必要步骤。**

### ⭐ 三个最推荐的位置

| 位置 | 为什么 | 难度 |

| **③ 输入框上方** | 每次对话都看到 | ⭐⭐⭐ 中 |

## 三、⭐⭐ 五种截流方式的优先级

| 方式 | 效果 | 难度 | 是否推荐 |
|---|---|---|---|
| **① README 放二维码** | 中（只看到仓库的人看） | ⭐ 最低 | ✅ **必做** |
| **② package.json homepage** | 中（市场站会显示） | ⭐ 最低 | ✅ **必做** |
| **③ 设置页放二维码** | **高**（装完必看） | ⭐⭐ 低 | ✅✅ **最推荐** |
| **④ 插件输出末尾水印** | 低（但长期） | ⭐ 最低 | ✅ 做 |
| **⑤ 扫码配对即关注** | **最高**（功能即转化） | ⭐⭐⭐⭐ 高 | 🟡 需开发 |

## 四、⭐⭐⭐ 给你的具体方案（分三层）

### 第一层：零成本必做（今天就能做）

| 位置 | 怎么做 |
|---|---|
| **package.json homepage** | 改成你的公众号链接页/落地页 |
| **README 顶部** | 加一段「使用问题/更多行业内容，加群：[二维码]」 |
| **README 底部** | 加「作者其他插件」列表（6 个互相导流） |
| **插件返回内容末尾** | 加「—— 由 dsh-xxx 提供」 |

### 第二层：低门槛（改几行代码）

| 位置 | 怎么做 |
|---|---|
| **设置页** | 加一个「关于」Tab，放二维码 + 你的其他插件链接 |
| **首次运行提示** | 第一次调用时返回一句「更多话术加群」 |

### 第三层：高价值（需要开发）

| 位置 | 怎么做 |
|---|---|
| **扫码配对** | 做一个「扫码同步话术库」功能，扫码即关注 |
| **云端话术库** | 插件从你的服务器拉最新话术（服务器上放二维码/广告） |

## 五、⭐⭐ 6 个插件互相导流的写法

**每个 README 底部加：**

```markdown
## 作者其他插件

- [dsh-sales-script](链接) — 销售话术库
- [dsh-hr-toolkit](链接) — HR 工具箱
- [dsh-legal-toolkit](链接) — 法律工具箱
- [dsh-teacher-toolkit](链接) — 教师工具箱
- [dsh-finance-toolkit](链接) — 财务工具箱
- [dsh-ops-toolkit](链接) — 运营工具箱

## 联系作者

使用问题 / 定制需求：[公众号二维码]
```

**→ 6 个插件形成流量闭环：装任意一个 → 看到其他 5 个 → 装更多 → 都导向你的公众号。**

## 六、⭐⭐ 一个实测的对比：做与不做

| 插件 | 下载 | 有截流吗 |
|---|---|---|
| **brewreel** | 172 | ✅ **有**（公众号私信 + 打赏） |
| misakanet | 544 | ✅ 有（导到 misakanet.org） |
| ccsafetynet | 57,332 | ✅ 有（导到 ccsafetynet.com） |
| dsh-deja | 1,273 | ✅ 有（导到 github.io 文档） |
| **大部分 ★0 插件** | 0-10 | ❌ **没有** |

### ⭐ 规律

> **有截流的插件，下载量明显更高（因为它们有「站」可以宣传）。**
> **没截流的插件，即使功能好也没人知道。**

## 七、⭐⭐ 我推荐的做法（结合你的 6 个插件）

| 步骤 | 做什么 | 成本 |
|---|---|---|
| **1** | 6 个 README 都加「作者其他插件」+ 公众号 | 10 分钟 |
| **2** | 6 个 package.json homepage 都改成同一个落地页 | 5 分钟 |
| **3** | 做一个简单的落地页（GitHub Pages） | 30 分钟 |
| **4** | 落地页上放：6 个插件介绍 + 公众号二维码 + 打赏 | 30 分钟 |
| **5** | 插件输出末尾加水印 | 10 分钟 |

**总计约 1.5 小时，就能形成完整截流闭环。**
