## 二、⭐⭐⭐ 三个关键发现

### 发现 1：privacy 是空分类（0 个插件）

| 项 | 数据 |
|---|---|
| 分类名 | **privacy** |
| 插件数 | **0** |
| 中文分类页 | ✅ 存在 |

**→ 这是一个「有分类页但没有插件」的真空。**

**可能原因：**

| 原因 | 说明 |
|---|---|
| ① 新开的分类 | 还没人提交 |
| ② 隐私类插件很少 | 大家都做功能不做隐私 |
| ③ 需求弱 | 用户不太关心隐私（但他们关心安全） |

### 发现 2：ui 是最拥挤的（1,189 个）

| 数据 | 值 |
|---|---|
| 插件数 | **1,189** |
| 平均下载 | **1,510** |
| 占比 | 1,189/6,378 = **19%** |

**→ 每 5 个插件就有 1 个是 ui 类。**

### 发现 3：session 的平均下载最高（5,439）

| 数据 | 值 |
|---|---|
| 插件数 | 445 |
| 平均下载 | **5,439** |
| 最高 | **1,772,945**（billion-context） |

**→ 但被 billion-context 一家占了 73%。**

## 五、⭐⭐ 分类对 SEO 的影响

### 分类名会出现在 title 里

```
title: owner/repo — dsh plugin · {分类名}
```

| 我们的分类 | title 会变成 |
|---|---|
| usage | `xxx — dsh plugin · Usage` |
| workflow | `xxx — dsh plugin · Workflow` |

### ⭐ 分类页也是 SEO 入口

| 事实 | 说明 |
|---|---|
| 24 个分类页 × 2（中英文） | = **48 个分类页面** |
| 每个分类页列出该类所有插件 | 你的插件会出现在分类页 |
| 分类页也有 SEO 权重 | 从分类页能导流到你的插件页 |

**→ 分类选对了，能多一个 SEO 入口。**

## 六、⭐⭐ 一个策略建议

### 如果想最大化曝光

| 策略 | 说明 |
|---|---|
| **① 分散到不同分类** | 7 个插件分到 usage/workflow/docs 三类，覆盖更多分类页 |
| **② 抢占空分类** | privacy 有 0 个插件，如果你做隐私类插件就能独占 |
| **③ 避开 ui** | 1,189 个，最拥挤 |

### ⭐ 具体建议

| 插件 | 分类 | 覆盖 |
|---|---|---|
| cost-advisor | **usage** | 分类 1 |
| sales-script | **workflow** | 分类 2 |
| hr-toolkit | **workflow** | 分类 2 |
| legal-toolkit | **docs** | 分类 3 |
| teacher-toolkit | **workflow** | 分类 2 |
| finance-toolkit | **docs** | 分类 3 |
| ops-toolkit | **workflow** | 分类 2 |

**→ 覆盖 usage / workflow / docs 三个分类页。**

## 七、⚠️ 诚实说明

| 项 | 说明 |
|---|---|
| **24 个分类是实测** | 从 sitemap 提取，中英文各 24 个 |
| **各分类数量是实测** | 从 6,378 插件索引统计 |
| **privacy 0 个是实测** | 分类页存在但没插件 |
| **分类是我们自己填的** | package.json 的 category 字段 |
| **站点是否按我们的 category 分类** | ⚠️ **未验证——可能它自己判断** |
