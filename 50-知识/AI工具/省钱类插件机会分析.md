# 省钱类插件机会分析：哪个细分最值得做

> **上轮发现「省钱」是最强需求。这轮拆到细分，找可做的空白。**
> **结论：token 优化已被占（211 万下载），但「成本归因」只有 4 个且 0 下载——要么是真空，要么是伪需求。**

## 一、⭐⭐⭐ 七个省钱细分的实测数据

| 细分 | 插件数 | 总下载 | 平均下载 | 判断 |
|---|---|---|---|---|
| **① token 优化** | **173** | **2,114,770** | **12,224** | 🥇 **最热（已被占）** |
| ② 预算控制 | 167 | 514,352 | 3,080 | 🥈 有需求 |
| ③ 峰谷价 | 119 | 421,734 | 3,544 | 🥉 有需求 |
| ④ 模型选择 | 339 | 304,708 | **899** | 🟡 拥挤但均量低 |
| ⑤ 上下文精简 | 154 | 290,903 | 1,890 | 🟡 |
| ⑥ 缓存 | 170 | 220,464 | 1,297 | 🟡 |
| **⑦ 成本归因** | **4** | **0** | **0** | ❓ **空白但零下载** |

## 二、⭐⭐⭐ 头部省钱插件在做什么（学它们）

### 1. billion-context（177 万下载）

| 项 | 内容 |
|---|---|
| 做什么 | **上下文压缩** |
| 核心卖点 | **「省 5 倍 token」+「小窗口 100k 足矣」+「支持几十亿 token 单会话」** |
| star | 2,130 |
| 仓库 | `ranxianglei/billion-context` |

**⭐ 它同时解决「省钱」和「能力」两件事——这是它 177 万下载的原因。**

### 2. whale-widget（19.9 万下载）

| 项 | 内容 |
|---|---|
| 做什么 | **右下角常驻挂件** |
| 显示 | 余额、今日已用、每轮消耗（含峰谷价） |
| 特色 | **余额预警 + 今日预算 + 30+ 厂商模板** |
| star | 5,570 |
| 关键 | **「数据全在本机，无遥测」** |

**⭐ 它靠「好看 + 常驻曝光 + 隐私承诺」赢了。**

### 3. dsh-context（15.6 万下载）

| 项 | 内容 |
|---|---|
| 做什么 | **上下文洞察面板** |
| 功能 | Context 仪表盘 + `/context` 命令 + Context 浏览器 |
| 看什么 | 分类组成、内容详情、演进趋势、压缩/注入事件 |
| star | 2,671 |

**⭐ 它做的是「让你看见上下文里有什么」——诊断型工具。**

### 4. dsh-cost-meter（10.6 万下载）

| 项 | 内容 |
|---|---|
| 做什么 | **会话费用芯片** |
| 显示 | 实时分桶 Token 用量、高峰/非高峰费率、**到下次费率切换的倒计时** |
| star | 477 |

**⭐ 它靠「倒计时」这个细节赢了——提醒用户错峰。**

## 三、⭐⭐⭐ 四个头部的共同规律

| 规律 | 证据 |
|---|---|
| **① 都做「省钱」** | billion-context 省 token、whale 显示消耗、cost-meter 显示费率 |
| **② 都做「可视化」** | 挂件、面板、芯片、仪表盘 |
| **③ 都有「提醒」功能** | 余额预警、预算上限、费率倒计时 |
| **④ 都强调隐私** | whale 明确写「数据全在本机，无遥测」 |

### ⭐ 一条隐含规律

> **用户不是要「省钱工具」，是要「知道自己在花多少钱」。**
> **知道了，才会自己去省。**

## 四、⭐⭐ 「成本归因」：唯一的真空

### 数据

| 项 | 数据 |
|---|---|
| 插件数 | **4 个** |
| 总下载 | **0** |
| 样本 | `ybkkasi`、`dsh-usage-orb` |

### ⭐⭐ 两种解释

| 解释 | 含义 | 判断 |
| **① 真空白** | 没人做，因为没人想到 | 🟡 可能 |
| **② 伪需求** | 有人试过，但没人要 | 🟡 **可能更大** |

### 为什么可能是伪需求

| 原因 |
|---|
| **「归因」太抽象** | 用户想知道「这轮花了多少钱」，不想知道「这笔钱该算到工具输出还是系统提示词」 |
| **成本归因是给开发者看的** | 普通用户不需要 |
| **已有插件覆盖了部分** | dsh-bill 有「费用标签页」把花费归因到工具输出/模型输出/系统提示词/终端命令 |

**⚠️ 注意：dsh-bill（4,266 下载）已经做了「费用归因」的一部分。**

## 五、⭐⭐ 那什么才是可做的？

| 方向 | 空白度 | 需求强度 | 判断 |
|---|---|---|---|
| token 优化 | 🔴 173 个，头部 177 万 | ✅✅ 极强 | ❌ 打不过 |
| 预算控制 | 🟡 167 个 | ✅ 强 | 🟡 需差异化 |
| **峰谷价提醒** | 🟡 119 个 | ✅ 强 | ✅ **可做（细节取胜）** |
| 模型选择 | 🔴 339 个 | 🟡 中 | ❌ 太挤 |
| 上下文精简 | 🟡 154 个 | ✅ 强 | 🟡 需差异化 |
| 缓存优化 | 🟡 170 个 | 🟡 中 | 🟡 |
| 成本归因 | ✅ 4 个 | ❓ 未知 | ⚠️ **风险大** |

### ⭐⭐⭐ 一个被忽略的角度

**看四个头部的「共同缺失」：**

| 头部做了什么 | 没做什么 |
|---|---|
| 显示花了多少钱 | **没告诉你「怎么少花」** |
| 显示费率倒计时 | **没自动帮你切换到便宜时段** |
| 显示上下文组成 | **没自动精简** |
| 显示 token 用量 | **没给出优化建议** |

**→ 「诊断」都做了，「处方」没人做。**

## 六、⭐⭐⭐ 我推荐的选题：省钱建议器

### 定位

| 项 | 内容 |
|---|---|
| 插件名 | `dsh-save-money` 或 `dsh-cost-advisor` |
| **做什么** | **分析你的使用习惯，给出具体省钱建议** |
| 差异化 | **不是显示花了多少，是告诉你「这样能省多少」** |
| 依据 | 4 个头部都在做诊断，没人做处方 |

### 核心功能（可落地）

| 功能 | 实现 |
|---|---|
| **① 峰谷价提醒** | 读当前时间 + DeepSeek 峰谷规则，提示「现在贵，X 小时后便宜一半」 |
| **② 模型建议** | 根据任务类型（简单问答/代码/长文）推荐更便宜的模型 |
| **③ 缓存优化建议** | 提示「你的系统提示词每次都变，导致缓存失效」 |
| **④ 上下文精简建议** | 提示「这个会话已 80k，建议开新会话」 |
| **⑤ 月度省钱报告** | 统计「如果按建议做，本月能省 X 元」 |

### 为什么这个能做

| 理由 |
|---|
| **数据都在本地** | 不需要联网，不涉及隐私 |
| **不重复头部** | 头部做显示，我们做建议 |
| **可量化** | 「能省 X 元」比「显示花了 X 元」更有冲击 |
| **技术简单** | 读会话日志 + 规则引擎，不需要复杂算法 |

## 七、⭐⭐ 实施难度评估

| 部分 | 难度 | 说明 |
|---|---|---|
| 读会话日志 | ⭐⭐ 低 | DSH 有 session 日志 |
| 峰谷价规则 | ⭐ 最低 | 公开规则 |
| 模型价格表 | ⭐⭐ 低 | 已有 models.dev |
| 建议引擎 | ⭐⭐⭐ 中 | 规则判断 |
| UI 展示 | ⭐⭐⭐ 中 | 需要前端 |

**→ 如果只做「工具 + 文本输出」（不做 UI），难度降到 ⭐⭐。**

| 项 | 说明 |
|---|---|
| **七细分数据是实测** | 用关键词搜 6,378 个插件 |

| **「成本归因是伪需求」是推断** | 基于「4 个插件 0 下载」+「已有插件覆盖部分」 |
