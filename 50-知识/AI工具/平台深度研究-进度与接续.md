## 一、方法（已定型，别改）

jjq 定的标准，每个平台都要做到：

| 要求 | 标准 |
|---|---|
| 抓取数量 | **不少于 200 条** |
| 时间范围 | **近三个月内** |
| 抓取方式 | **串行，不要限流**（每页间隔 35–50 秒） |
| 论证维度 | **至少 5 个方面**证明真实、可做 |
| 外部评价 | 用通用引擎找第三方评价 |

### 5 个论证维度（固定用这套）

1. **新鲜度**——发布时间分布，是否近期
2. **竞争度**——提案数/投标数，有没有人抢
3. **预算/价格**——中位数、分布区间
4. **需求质量**——描述完整度、有无技术栈
5. **客户/项目可信度**——状态是否 open、完成时间是否残留、客户注册时长、是否验证

### 必查的四个"假数据"陷阱

| 陷阱 | 怎么查 |
|---|---|
| 项目是编的 | 抽查详情页，确认独立存在 |
| 数据陈旧 | 逐条看 posted_dt 分布 |
| 挂很久没人做 | 看 item_state 和 expiry_dt |
| 做完了没更新 | 看 completed_dt 是否 null |

### 4.4 抓取通道要点（血泪教训）

| 情况 | 用什么 |
|---|---|
| 普通站 | `curl -x http://127.0.0.1:7897`（**必须 curl，Node 的 http/fetch 会 400**） |

| Chrome 重复访问被拦 | 间隔 30 秒以上再抓 |
| 数据在 React 里 | 找 `window.XXX.initialState=` 直接解析 JSON |

## 五、换新平台时的操作步骤

1. **确认数据结构**：先用 Chrome 抓一次首页，看数据藏在哪（HTML / React state / API）
2. **找分页**：看有没有 `?page=N` 或 `total-items` 元数据
3. **改抓取脚本**：复制 `pph-scrape.mjs`，改 URL 和解析逻辑
4. **串行跑**：每页间隔 35–50 秒，边跑边落盘（断点续跑）
5. **跑 verify-5d.mjs**：输出 5 维打分
6. **抽查 8–10 个详情页**：确认项目真实存在
7. **搜索外部评价**：Sitejabber / Trustpilot / Reddit / 独立测评站
8. **写报告**：照 [[平台研究-01-PeoplePerHour-深度版]] 的结构
9. **更新这篇的进度表**
