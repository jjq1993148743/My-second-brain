# 我做 DSH 插件前，先扒了 6,378 个插件的数据

结果发现：**51% 的插件，一个下载都没有。**

但同时，有些插件上线 3 天就冲到日均 6,000 下载。

差别在哪？我把数据拆开看了。

---

## 一、先看残酷的现状

| 数据 | 数值 |
|---|---|
| 总插件 | **6,378** |
| **零下载** | **3,227（51%）** |
| 下载过千 | 1,867（29%） |
| 有下载但不到千 | 1,284（20%） |

**一半的插件，发出来就沉了。**

---

## 二、那成功的那些，有什么共同点

### 我统计了「下载过万」的插件描述里的关键词

| 关键词 | 出现在多少个成功插件里 |
|---|---|
| **UI** | 39 |
| **模型** | 24 |
| **git** | 14 |
| **搜索** | 11 |
| **上下文** | 11 |
| **API** | 11 |
| **token** | 10 |
| **图片** | 9 |
| **技能** | 9 |
| **浏览器** | 8 |
| **界面** | 7 |
| **记忆** | 7 |

### ⭐ 排第一的是「UI」（39 个），第二是「模型」（24 个）

**这说明：**
- **UI 类需求最大**（用户想改造界面）
- **模型相关次之**（换模型、接订阅）

**但注意：「UI」虽然出现最多，但 ui 分类有 1,189 个插件（最拥挤）。**

**→ 出现频率高 ≠ 机会大。要看「平均下载」。**

### ⭐⭐ 成功插件（下载过万）的类别分布

**全生态只有 107 个插件下载过万（占 1.7%）。它们分布在：**

| 类别 | 成功数 | 该类总数 | 成功率 |
|---|---|---|---|
| **ui** | **14** | 1,189 | **1.2%** |
| **model** | **11** | 349 | **3.2%** |
| session | 8 | 445 | 1.8% |
| memory | 8 | 272 | **2.9%** |
| tools | 8 | 835 | **1.0%** |
| theme | 6 | 243 | **2.5%** |
| browser | 5 | 139 | **3.6%** |
| skill | 5 | 242 | 2.1% |
| remote | 5 | 196 | **2.6%** |
| vision | 4 | 134 | **3.0%** |

### ⭐⭐⭐ 这个表才是关键

**「成功率」= 成功数 ÷ 该类总数。**

| 排名 | 类别 | 成功率 | 含义 |
|---|---|---|---|
| **1** | **browser** | **3.6%** | 最容易成功 |
| **2** | **model** | **3.2%** | 第二容易 |
| **3** | **vision** | **3.0%** | 第三 |
| 4 | memory | 2.9% | |
| 5 | remote | 2.6% | |
| 6 | theme | 2.5% | |
| ... | | | |
| **倒数** | **tools** | **1.0%** | 最难成功 |
| **倒数** | **ui** | **1.2%** | 第二难（虽然成功数最多） |

**→ ui 类成功数最多（14 个），但成功率只有 1.2%（因为总共有 1,189 个）。**
**→ browser 类只有 5 个成功，但成功率 3.6%（总共才 139 个）。**

### 看下载榜前 5 都在做什么

| 插件 | 下载 | 做什么 |
|---|---|---|
| **billion-context** | **1,772,945** | **省 5 倍 token** |
| dsh-market | 598,350 | 插件市场 |
| dsh-codex-ui | 232,002 | UI 改造 |
| DSH-better-sidebar | 208,637 | 更好的侧边栏 |
| whale-widget | 199,295 | 显示余额（省钱可视化） |

**5 个里 2 个直接跟「钱」有关（billion-context 省 token、whale-widget 显示余额）。**

**但注意：dsh-market 和 dsh-codex-ui 是「基础设施类」——它们不省钱，但它们让 DSH 更好用。**

## 三、四个真实案例：什么样的插件能 3 天冲上来

## 四、三个可复制的公式

### 公式 1：省钱 / 省时间

| 做法 | 例子 |
|---|---|
| 省 token | billion-context（177 万下载） |
| 显示花了多少钱 | whale-widget（19.9 万） |
| 自动压缩上下文 | 各类 compact 插件 |

### 公式 2：防损失（恐惧驱动）

| 做法 | 例子 |
|---|---|
| 防误删 | cc-safety-net（4 天 14,333/天） |
| 防泄密 | 权限类 |
| 防跑偏 | 输出校验类 |

### 公式 3：填环境坑

| 做法 | 例子 |
|---|---|
| Windows 适配 | dsh-ops（5 天 4,576/天） |
| 中文优化 | 中文分词/输入法 |
| 特定 IDE 适配 | VSCode/JetBrains |

## 五、那些沉了的，踩了什么坑

| 坑 | 具体表现 |
|---|---|
| **描述模糊** | 「提升效率」「增强体验」——用户看不懂 |
| **解决伪需求** | 用户其实不需要 |
| **没被收录** | 只在 GitHub，没提交目录站 |
| **名字看不懂** | `dsh-m` 这种（虽然它火了，但是运气） |
| **没有一句话说清价值** | README 第一段讲技术不讲用途 |
