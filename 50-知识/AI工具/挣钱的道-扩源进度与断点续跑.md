## 五、关于「信息差」的判断（回答 jjq）

jjq 问：我们从信息差角度，迈入突破这道门槛了吗？

**我的判断：迈入了一半。**

### 已经突破的

| 能力 | 证据 |
|---|---|
| **不依赖搜索引擎** | `web_search`/`web_fetch` 全废，但找到了 4 条可行通道（本机代理 / Chrome headless / 搜狗微信 / GitHub API） |
| **从「页面」里挖源，不是从「关键词」里** | 主流打法是搜关键词，我们是抓真实页面的 `<a href>`。**1,004 个源没有一个是猜的** |
| **会用 GitHub 这种「非大众」入口** | awesome 列表是程序员才摸得到的东西，jjq 说「并不是所有人都能玩得转」——对。已挖 60+ 个列表 |
| **会打「算法放弃的地方」** | 十年之约（1,948 博客/无算法）、独立博客联盟、Discuz 老站 |
| **会绕 Cloudflare** | Chrome headless 突破 TLS 指纹（Reddit 实测拿到 190KB） |

### 还没突破的

| 缺口 | 说明 |
|---|---|
| **通用搜索能力** | 不能主动发现「从没听说过的新站」，只能顺链摸。这是最大短板 |
| **一手访谈** | 库里最重磅的《真实抱怨清单》是别人做的。海外多个案例的共同模式是「去线下听小老板抱怨」，这层完全没碰 |
| **群的渗透** | 微信群/QQ群/Telegram/Discord 是信息密度最高的地方，但只在页面里发现了入口，没进去过 |
| **交叉验证** | 同一条路子往往只找到一个信源 |

> **结论：我们从「找信息」进入了「会找信息」，但还没到「信息主动来找我们」。**
> 下一步真正的跃升是：**把 1,004 个源变成可持续订阅的流水线**（RSS/API），让新信息每天自动流进来，而不是每次重新挖。
