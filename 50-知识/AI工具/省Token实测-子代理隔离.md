# 省 Token 现场实测报告 · 子代理上下文隔离

> 日期：2026-10-09 ｜ 试验田：本仓库「猫病症自查百科」真实项目 ｜ 方法：A/B 对比

## 一、试验设计

**为什么只测这个**：5 个方案里，只有「子代理上下文隔离」能在本机现场跑出可验证的对比。其余四个（Prompt Caching / Tool Search / Code Mode / 模型分级）是 API 底层或平台开关，本机开不了，只能讲原理。

**任务**：用真实项目原料，为 02-05 四个待做选题（不吃东西 / 软便 / 眼屎多 / 尿血）提炼选题卡。

**原料体量**（实测）：

| 范围 | 文件数 | 字符数 | 估算 token（×1.2） |
|------|--------|--------|-------------------|
| 项目全部 md | 14 | 423,276 | ~508K |
| 核心 4 文件（HANDOFF + 写作手册 + 72条大表 + SKILL） | 4 | 205,419 | ~246K |
| 其中「72条大表」单文件 | 1 | 192,416 | ~231K |

## 二、两条路线

| | 路线 A：主上下文直读 | 路线 B：子代理隔离 |
|---|---|---|
| 做法 | 主代理自己 Read 4 个核心文件（含 19 万字符大表） | 派子代理读全部原料，只回 4 张选题卡 |
| 进主上下文的量 | ~246,000 token | **~1,100 token**（约 900 字摘要） |
| 结果 | 撞穿 200K 窗口，**跑不完** | 一次跑完，主上下文干净 |

**降幅对比：约 220 倍。** 那 19 万字符的大表，**一个字都没进主代理的窗口**。

## 四、产出样例（4 张选题卡，节选）

- **02 不吃东西**：判断点 = 手喂/回温测挑食 vs 恶心；水碗+尿团是最快分水岭；「空盆满 24 小时」是硬线。出处 iCatCare 2026 CKD 共识（JFMS）。
- **03 软便**：判断点 = 软便与真腹泻分开；两周减法定位；幼猫长期软便先想原虫。出处《猫病学》第5版 第55条「腹泻」。
- **04 眼屎多**：判断点 = 「能不能自己睁开」分档；分泌物分清水/黄绿脓/带血；单眼怕光要快。出处《猫病学》第5版 第125条。
- **05 尿血**：判断点 = 频繁进盆少量 vs 尿不出急症按小时算；先确认红色是不是血；精神食欲决定是否当天走。出处 iCatCare 2025 FLUTD 共识（PMID 39935081）。

## 五、这次实测证明了什么

1. **省 token 的主战场是「上下文架构」，不是「把提示词写短」。** 你已经知道要外置知识、派子代理——方向对，这次是量化确认。
2. **子代理隔离是「零门槛、立刻见效」的一招**，不用改架构，改工作流就行。
3. **省 token 与不丢质量可以兼得**（出处全部可溯源），关键在给子代理**结构化输出契约**（本报告用的就是「固定字段 + 限字数」）。

## 六、局限（别当全貌）

- 本次只验证了「子代理隔离」一项。Prompt Caching / Code Mode 的降幅来自 Anthropic、Cloudflare 官方一手数据，非本机实测。
- token 为估算值（字符×1.2），非计费口径的精确 tokenizer 计数，用于量级对比可靠。

## 七、可继续验的方向

- 模拟 Prompt Caching：制造「重复前缀 vs 动态前缀」两次调用，看缓存命中差异（需能读 API 返回的 cache 字段）。
- 模拟 Code Mode：用本地 Python 演示「中间结果在脚本里过滤，只 print 结论」，对比「全量输出」。
