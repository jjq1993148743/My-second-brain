# 省钱建议器已做出来（第 7 个插件）

> **按数据做的：不是显示花了多少，是告诉你「这样能省多少」。**
> **实测通过：峰谷价判断正确，输出 575-654 字符的完整建议。**

## 一、⭐⭐⭐ 为什么做这个

### 数据依据（前一轮实测）

| 发现 | 数据 |
|---|---|
| 省钱是最强需求 | billion-context **177 万**下载 |
| 但头部都在做「诊断」 | whale-widget 显示余额、dsh-context 显示上下文、cost-meter 显示费率 |
| **没人做「处方」** | 没人告诉你「具体怎么省」 |

### ⭐ 定位

| 项 | 内容 |
|---|---|
| 插件名 | **`dsh-cost-advisor`** |
| 一句话 | **不只告诉你花了多少，告诉你这样能省多少** |
| 差异化 | **诊断 → 处方** |

## 二、⭐⭐⭐ 五项建议（实测输出）

### ① 峰谷价提醒（最实用）

**实测输出：**
```
## ① 峰谷价
- **现在是高峰时段**（北京时间 08:30-17:30），价格较贵
- **再过 4 小时 37 分钟 就进入闲时**，价格约降一半
- 建议：不急的任务可以等闲时再跑
```

**⭐ 它会算出「还有多久进入闲时」——这是最具体的建议。**

### ② 模型选择建议

| 任务类型 | 建议 |
|---|---|
| simple（简单问答） | 轻量模型就够，成本降 5-10 倍 |
| code（代码） | **规划用便宜模型、编码用主力** |
| longform（长文） | **先列大纲再分段写**，避免每轮带全部历史 |

### ③ 缓存优化

```
## ③ 缓存优化
- **缓存命中能省 90% 的输入 token 费用**
- 检查点：
  - 系统提示词是否每轮都在变？（变了缓存就失效）
  - 是否在会话开头就塞了大量文件？（可以后置按需读）
  - 是否频繁改 AGENTS.md？（改一次全失效）
```

### ④ 上下文精简（智能判断）

| 上下文大小 | 建议 |
|---|---|
| > 80k | **建议开新会话** + 用压缩插件 |
| 40-80k | 留意增长 |
| < 40k | 很健康 |

**实测：输入 95k 时，正确提示「已偏高，建议开新会话」。**

### ⑤ 能省多少（量化）

| 做法 | 预计节省 |
|---|---|
| 全部任务错峰到闲时 | **约 50%** |
| 简单问答换轻量模型 | 该部分 **80-90%** |
| 提高缓存命中率 | 输入 token **最高 90%** |
| 及时开新会话 | 长会话 **30-50%** |

**「如果四项都做，整体成本通常能降 40-60%。」**

## 三、⭐⭐ 技术实现

### 核心逻辑

| 部分 | 实现 |
|---|---|
| 峰谷价判断 | 硬编码 DeepSeek 规则（08:30-17:30 高峰） |
| 倒计时计算 | 算当前时间到 17:30 的差值 |
| 上下文判断 | 用户传入 token 数，按阈值给建议 |
| 任务类型 | 枚举参数 simple/code/longform |

### ⭐ 为什么这样设计

| 设计 | 原因 |
|---|---|
| **不读会话内容** | 保护隐私，只读时间 |
| **参数可选** | 不填也能给通用建议 |
| **零依赖** | 装即用 |
| **纯文本输出** | 不需要前端，降低门槛 |
