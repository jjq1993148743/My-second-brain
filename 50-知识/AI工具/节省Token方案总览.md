# 节省 Token 方案总览

> 创建：2026-10-09 ｜ 来源：Anthropic 官方工程博客 ×2、Cloudflare Code Mode、Prompt Caching 实测
> 一句话：省 token 的主战场早已不是「把提示词写短」，而是**上下文架构**——工具定义、中间结果、会话历史这三块怎么不塞进模型。

---

## 0. 先看清钱花在哪（成本结构）

Token 消耗的三大头：

| 大头 | 说明 | 典型量级 |
|------|------|----------|
| 工具定义 | 每个 MCP 工具的定义（desc + schema）全量塞进上下文 | 5 个 MCP ≈ 55K；Anthropic 内部见过 **134K** |
| 中间结果 | 每次工具返回的原始数据流回模型 | 一份 2 小时会议转录来回两趟 ≈ 50K；1 万行表格全进窗口 |
| 会话历史 | 多轮对话累积，每轮重发 | 线性增长 |

**关键认知**：输入 token 在 agent 循环里会被**反复重发**，所以砍掉 1 个常驻工具的 1K 定义，省的是每一轮的 1K。

## 1. 方案清单（按性价比排序）

| # | 方案 | 一句话 | 降幅 | 落地难度 | 谁在用 |
|---|------|--------|------|----------|--------|
| 1 | **Prompt Caching** | 重复前缀命中缓存，读价 0.1× | 成本 ≤90%↓ / 延迟 ≤85%↓ | 极低（一行配置） | Claude Code 底层、几乎所有生产 API |
| 2 | **Subagent 上下文隔离** | 脏活（大量抓取/搜索）丢给子代理，只回摘要 | 主上下文 50-80%↓ | 中 | Claude Code、各类 agent 框架 |
| 3 | **Tool Search Tool** | 工具定义延迟加载，用时才搜出 3-5 个 | 85%↓ | 中 | Anthropic 平台（Beta） |
| 4 | **Code Mode / 代码执行** | 中间结果在沙箱过滤聚合，只回结论 | **98.7%-99.9%↓** | 高（要沙箱） | Cloudflare、Anthropic、Block |
| 5 | **模型分级 + 少读少写** | 简单活走便宜模型；别重复读同一文件 | 看场景 | 低 | 通用实践 |

## 2. 逐条拆解（含硬数字）

### 2.1 Prompt Caching —— 最便宜的一刀

- **机制**：相同前缀在 TTL（默认 5 分钟）内复用，不重算。
- **价格**：缓存读 ≈ 基础输入价 **10%**；缓存写 ≈ **125%**（仅首次）。
- **条件**：结构必须稳定——固定内容放前面（system / 工具定义 / 大文档），变量放后面。
- **坑**：动态时间戳、随机排序会让缓存**永不命中**。

### 2.2 Subagent 上下文隔离 —— 最实用的工程手段

- **机制**：把「读 50 个文件 / 搜 20 个网页」这种脏活交给子代理，子代理的原始过程不进主上下文，主代理只收一份摘要。
- **本机实证**：workbuddy/Claude Code 的 Explore、general-purpose 子代理就是这个用法。
- **配套**：`/compact`（压缩历史）、精简 system prompt、用 Skill 做知识外置。

### 2.3 Tool Search Tool —— 专治「工具太多」

- **机制**：工具定义打 `defer_loading: true`，首轮只加载搜索工具（~500 token），模型按需搜出相关工具再展开。
- **数字**（Anthropic 官方，2025-11-24）：
  - 传统：50+ MCP 工具定义 ~72K token，开工前合计 **~77K**
  - Tool Search：预载 ~500 + 按需 ~3K = **~8.7K**
  - **省 85%**；可用上下文 191,300 vs 122,800
- **副作用加成**：选工具准确率大涨——Opus 4 **49%→74%**，Opus 4.5 **79.5%→88.1%**
- **不划算的场景**：工具库很小（<10 个）、几乎每个会话都用全部工具。

### 2.4 Code Mode / 代码执行 —— 最狠的一招（"最强"）

- **机制**：把 MCP 工具暴露成 **TypeScript/Python 代码 API**，模型**写代码**调用，中间结果在沙箱里过滤/聚合，**只有最终结论回到上下文**。
- **数字**：
  - Anthropic：**150,000 → 2,000 token（省 98.7%）**
  - Cloudflare Code Mode：2500+ 个 API 端点 = **1,170,000 token → 约 1,000 token**，缩成 `search()` + `execute()` 两个函数（**省 99.9%**）
- **附带好处**：隐私（敏感数据 tokenize 后过沙箱，模型看不到原文）、状态持久化（写文件续跑）、技能复用（存成可执行函数）。
- **代价**：需要安全沙箱（沙箱、资源限额、监控），**实现复杂度最高**。

### 2.5 Programmatic Tool Calling（编程式工具调用）

- 代码执行的同族招式：多步工具链写在 **一段代码**里跑（循环 / 条件 / 并行），不再「每步回模型推理一次」。
- **数字**：复杂研究任务 token **43,588 → 27,297（~37%↓）**；检索准确率 25.6%→28.5%。
- **官方案例**：Claude for Excel 用它读写上万行表格不爆上下文。

### 2.6 Tool Use Examples

- 给工具挂 1-5 个**真实调用示例**，教模型「惯例」（日期格式、可选字段何时填）。
- **数字**：复杂参数处理准确率 **72% → 90%**。
- 跟省 token 无直接关系，但**减少返工 = 减少 token**。

### 2.7 Skills vs MCP —— 两者不冲突，分工不同

| 维度 | MCP | Skills |
|------|-----|--------|
| 定位 | 连**外部系统**（发邮件、查库、调 API） | 装**知识/流程**（怎么做某件事） |
| 占用 | 工具定义进上下文（贵） | 三级渐进披露，启动只加载 name+description（便宜） |
| token 特性 | 工具越多越贵 | 正文和附件**按需读取**，可近乎无限扩展 |
| 关系 | Skills 可以编排 MCP 工具 | MCP 给 Skills 提供手和脚 |

**一句话**：Skills 是「省 token 的天然盟友」（知识不外置就烧上下文），MCP 是「主要 token 税源」（工具定义 + 中间结果）。

## 3. 谁最强？谁大家都在用？

- **最强（降幅）**：**Code Mode / 代码执行**。98.7%-99.9%，且是行业共识方向——Anthropic 和 Cloudflare 独立研发出同一架构。
- **大家都在用（默认开）**：**Prompt Caching**。Claude Code 能"低价高效"，靠的就是它，大多数生产 API 默认依赖。
- **最实用（立刻见效）**：**Subagent 隔离 + Skills 外置知识**。不用改架构，改工作流就行。
- **前沿趋势**：工具调用正从「全塞上下文」转向「按需发现 + 代码编排」——Tool Search 是过渡方案，Code Mode 是终局。

---

## 4. 选型决策

| 你的痛点 | 先上哪张牌 |
|----------|-----------|
| 成本高、前缀重复 | Prompt Caching |
| 单次任务上下文爆 | Subagent 隔离 |
| 工具定义撑爆上下文 | Tool Search（或 Code Mode） |
| 中间结果太大、步骤太多 | Programmatic Tool Calling / Code Mode |
| 参数老填错、返工多 | Tool Use Examples |
| 简单任务也烧钱 | 模型分级 |
