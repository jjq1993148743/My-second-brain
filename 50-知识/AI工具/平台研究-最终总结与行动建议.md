## 二、⭐ 最终决策：三个梯队

### 🥇 第一梯队：值得实际投入

#### 1. Useme（波兰）—— 准入条件最稀缺

| 指标 | 数值 |
|---|---|
| 中位投标 | 20 人 |
| 中位预算 | €500 |
| 最高预算 | €20,000 |
| 开发类 | 27% |
| **公司主体** | **❌ 不需要** ⭐ |
| 语言 | 英语可用 |

**为什么第一：** 大多数欧洲平台都要求公司主体，它不需要。这是硬性准入优势。

**真实机会：** €20,000 的软件开发项目只有 **3 人投标**。

## 五、方法论沉淀

### 5 维验真框架
1. 新鲜度 — 时间类型 + 年龄分布 + 今日新增
2. 竞争度 — 中位投标数
3. 预算水平 — 中位数而非平均
4. 项目质量 — 描述完整度、技术栈匹配
5. 平台可信度 — 第三方评价 + 费率透明度

### 6 步识别僵尸项目
1. 查时间字段类型（相对时间可信）
2. 算年龄分布（中位数）
3. 看今天发布数量（0 = 危险）
4. 交叉验证状态字段
5. 验证竞争度异常
6. 看截稿时间

### 技术要点

| 情况 | 方案 |
|---|---|
| 普通站 | `curl -x http://127.0.0.1:7897` |
| SPA | Chrome `--dump-dom --virtual-time-budget=22000` |
| React 数据 | 找 `window.XXX.initialState=` |
| 分页无效 | 改用分类 URL |
| git push 失败 | `-c http.proxy=...` |
| 正则含 `/` | 用字符类 |

## 六、诚实说明：为什么没做到 50 个

| 类别 | 数量 |
|---|---|
| 成功抓取 | 14（含 4 个同源） |
| **去重后独立平台** | **10** |
| 技术不可行 | 26+ |

**原因：**
1. 大部分平台是 SPA — 项目列表在 JS 里
2. 强制登录 — Upwork、CrowdWorks、Lancers、Coconala
3. 无「项目列表」概念 — Fiverr（挂牌）、Patreon（订阅）
4. 同一系统多语言 — Freelancer 占 8 个域名、Freelancermap 占 3 个
5. 赏金类全需登录 — HackerOne、Bugcrowd、Algora 等 14 个

**这已经是公开可抓数据的极限。**
