# 省 Token 实测（三）：缓存真相与成本模型

> 日期：2026-10-09 ｜ 定价来源：Anthropic 官方价格页 2026-10-04 核对 ｜ 模型：Claude Sonnet 5.5

## 一、先回答那个关键疑问

**问**：我们说的"省 token"是不是都指「每次对话的上下文」？API 里重复上下文是低价的，是不是在 API 内部处理了？

**答：对了一半，另一半是误解。**

「省 token」在日常语境里**混指两件事**，必须拆开：

| 目标 | 含义 | 谁受影响 |
|------|------|----------|
| **省窗口占用** | 上下文里塞的 token 变少 | 能不能装下、模型注意力是否被稀释 |
| **省账单** | 花的钱变少 | 你的钱包 |

**缓存（Prompt Caching）只解决第二个，完全不解决第一个。** 官方文档原话：

> 缓存会改变上下文上限吗？不会。被缓存的 token **依然算在提示里，占用上下文窗口**。缓存改变的是重复输入的价格。

所以"API 内部处理了重复上下文"——对，它把**价格**处理了（降到 0.1×），但那些 token **照样占着你的窗口**。缓存不是"把内容搬走"，是"给同一段内容打折"。

## 二、成本模型实测（Sonnet 5.5，50K 前缀，调用 10 次）

| 策略 | 前缀费用 | 省幅 | 窗口占用 |
|------|---------|------|---------|
| 基线（不缓存） | $1.000 | — | 50,000 |
| ① 只上缓存 | $0.215 | 78% | **50,000（没变）** |
| ② 只精简上下文 | $0.200 | 80% | **10,000** |
| ③ 精简 + 缓存 | $0.043 | 96% | **10,000** |

**结论：两个杠杆是相乘关系，不是二选一。**
- 想省**钱** → 上缓存
- 想省**窗口**（同时省钱）→ 精简上下文
- 想最大化 → 先精简，再缓存

## 三、缓存不是万能：两个反直觉的坑

### 坑 1：间隔超过 TTL，缓存反而更贵

| 场景 | 不缓存 | 5分钟缓存 | 1小时缓存 |
|------|--------|-----------|-----------|
| 快速循环（间隔<5min） | $1.200 | **$0.215 最省** | $0.290 |
| 人工节奏（每10分钟一次） | $1.200 | **$1.500 比不缓存贵 25%！** | **$0.310 最省** |

原因：5 分钟缓存的 TTL 内没人用就失效，间隔超时后每次都要**重新写**（1.25× 溢价）。**选档口诀：间隔 <5 分钟用 5 分钟档；5-60 分钟用 1 小时档；只调一次别缓存。**

### 坑 2：只在稳定前缀上缓存

时间戳、新消息若落在缓存断点**之前**，哈希每次都变，永远读不到，白付写入溢价。

## 四、省 Token 方案矩阵（按目标分）

| 目标 | 手段 | 实测/官方数据 |
|------|------|--------------|
| **省钱** | Prompt Caching | 重复前缀省 78%-90%（依赖命中） |
| **省钱** | Batch API | 五折 |
| **省钱** | 模型分级（简单活走 Haiku） | Sonnet→Haiku 输入价 2→1 |
| **省窗口** | 子代理上下文隔离 | 主上下文 237K→504（-99.8%） |
| **省窗口** | 工具按需加载（Tool Search） | 官方 85%↓ |
| **省窗口** | 代码执行归约（Code Mode） | 官方 98.7%-99.9%↓ |
| **省窗口** | Skill 渐进披露 | 元数据 3,940 vs 全文 74,402（差 17.9×） |
| **省窗口** | 本地脚本处理大文件、只回结论 | 本环境最实用 |

## 五、重要提醒

- **Claude 4.7+ 换了新分词器，同样文本约多 30% token**（官方说明）。此前用旧模型量的数字会偏低。
- 本机 `token-audit` 用 cl100k_base，**与真实计费有偏差**，仅作量级参考。
- **本环境观测不到缓存命中**，上表缓存数字是**按官方定价的模型计算**，非本机实测。
- 最小可缓存长度：Sonnet 5.5 为 512 token，Haiku 4.5 为 4,096 token，低于则无法缓存。

## 六、一句话总结

**省 token = 省窗口（上下文工程） × 省钱（缓存/分级）。** 缓存打折但内容还在窗口里；真正的"减负"只能靠把不该进上下文的东西挡在外面。
