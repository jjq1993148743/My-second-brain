# 后端数据链路俯视图（backend-dataflow-diagram）

## 解决什么问题

手写代码时代的工程师脑子里有一张后端俯视图：一个请求进来，先过哪层、落哪个类、走哪条分发链、最后写哪张表。代码由 AI 代写后，这张图在人脑里消失了 —— 文件还在，但没人保证「知道它们怎么连起来」。

本技能把这张图重新画出来，**只画代码里真的存在的东西**。任意项目、任意业务流程都适用：先探测技术栈，再按同一套版式出图。

## 第 0 步 · 先判断技术栈（跨项目必做）

看仓库根目录的清单文件决定后续检索方式：

| 特征文件 | 栈 | 文件/方法长什么样 |
|---|---|---|
| pom.xml / build.gradle | Java / Spring | XxxController.java、`方法:行号` |
| package.json | Node / TS | xxx.controller.ts、路由注册 |
| pyproject.toml / requirements.txt | Python | views.py / routers/、函数 |
| go.mod | Go | handler/、`func XxxHandler` |
| *.csproj / *.sln | .NET | XxxController.cs |
| composer.json | PHP / Laravel | Controller.php |
| Gemfile | Ruby / Rails | app/controllers |

完整检索配方见 `references/stack-recipes.md`。**先读它，能省一半时间。**

## 版式（本技能的灵魂，改版式前先读完这一节）

### 八列，从左到右

| # | 列 | 默认列名 | 写什么 | 可省略 |
|---|---|---|---|---|
| 1 | req | 请求侧 | Web / App / 第三方，谁发起的 | 否 |
| 2 | gw | 接入层 | 网关 / Nginx / 反向代理 / 路由入口 | 单体可省 |
| 3 | svc | 服务 | 哪个进程 / 哪个应用 | 否 |
| 4 | mod | 模块 | 子模块 / 包 / 目录 | 小项目可省 |
| 5 | file | 文件 | 类名.java / 文件名 / mapper xml | 否 |
| 6 | method | 方法 | 方法名:行号 / 函数名 | 否 |
| 7 | ds | 存储 | 库名 / 数据源 / 缓存 / 队列 | 无存储可省 |
| 8 | table | 数据表 | 表名 / topic / key 前缀 | 无存储可省 |

列名可以按项目改写（前端项目：页面 → 组件 → Store → API → 请求方法 → 本地存储 → 数据结构），**但「从左到右越来越具体」这个语义不能变**。

### 行 = 服务段，行内横向对应

- **一行 = 一次请求经过的一个服务段**。A 服务这一行，右侧就是 A 里的模块、类、方法 —— 横向严格一一对应。
- **行从上到下 = 时间顺序**；格内多个芯片从上到下也是先后。
- 卡片右上角数字 = 全局步骤号，照 1→N 读就是完整一次请求。

### 视觉规则（每条都踩过坑，别改回去）

| 规则 | 原因 |
|---|---|
| **不画泳道线**，用淡色背景色带区分列 | 泳道线把图切得太碎 |
| **色带在卡片之下**（z-index 0 → 连线 1 → 卡片 2） | 线不能压卡片 |
| 色带宽度基准必须与内容表格一致（都 `min-width` + `width:100%`） | 否则 1fr 列宽不同步，**越往右越错位** |
| 表头 **sticky 冻结**（Excel 式），滚动容器 = 页面本身 | 容器 overflow-x 会让 sticky 失效 |
| 卡片 **等宽等高 100px**，四行栅格：状态+序号 14 / 业务名 20 / 代码 18 / 说明 18 + 3×4 gap + 上下 16 | 尺寸是算过的，改字号必须同步改高度 |
| 每行**单行省略号**，悬停 data-tip + title 出全文 | 换行会挤压 |
| 状态角标**只标例外**：外部（紫）/ 缺口（红虚线）/ 原型（黄虚线）；不打标 = 真实 | 满屏「真实」是噪音 |

### 连线规则（最容易返工的一节，按顺序照做）

1. **只走正交**：任何线段要么全水平、要么全垂直。渲染层有 orth() 保险：两点 x、y 同时不同就自动插拐角。
2. **同列直上直下**（2 个控制点），同行直左直右。**不许为了「进出不同点」把同轴连线掰弯。**
3. **只有跨行且跨列**才 4 点折弯，走**行间空隙中线**。
4. **走列缝 / 行缝中线**，留 >=6px 净空；线段**不得与卡片边线平行且贴近**（贴边看起来像卡片长了尾巴）。
5. **出线用卡片底/右缘中心，入线用顶/左缘中心** —— 进与出天然不同点，不需要偏移 hack。
6. 箭头：SVG `marker id="arrowhead"`，CSS `marker-end:url(#arrowhead)`，**两个 id 必须一字不差**（写错整张图没箭头）。
7. 进出「请求侧」的线用**虚线**（出网语义）。

## 工作流（五步）

### 第 1 步 · 锁定范围

把业务名翻译成仓库检索词，用证据说话：

1. 中文业务词（业务注释、枚举、常量里命中率高）
2. 英文驼峰/下划线变体（Member / member_ / MEMBER_）
3. 文件名 glob
4. 前端反查：API 封装目录里的 url 暴露后端**应该**有哪些接口；本地 mock 开关说明哪些接口**还没有**

产出：候选链路清单，每条一句话（谁发起 → 经过什么 → 落到哪）。一般 3~7 条。

### 第 2 步 · 逐条取证

每层都要打开文件确认，**行号当场读到**：

| 层 | 确认什么 | 常见坑 |
|---|---|---|
| 请求侧 | 真实请求路径、baseURL | 以为调了后端，其实是本地 mock |
| 接入层 | 端口、具体过滤器/中间件 + 行号 | 只写「网关」不写过滤器，等于没画 |
| 服务 | 请求真的跨进程了吗 | 接口定义在某处，实现在另一处 |
| 文件 | 文件名、路径 | 同名文件跨模块 |
| 方法 | 方法名 + 当前行号 | 注释里出现方法名 != 方法存在 |
| 存储/表 | 表名 + 谁写它 + 落哪个库 | 实体存在 != 有 Dao；mapper 指向的接口可能不存在 |

**查不到就标 gap**，并在 gaps[] 里写否定证据，例如：`XxxMapper.xml` 声明 namespace `...XxxDao`，但 glob 返回 0 个文件、xml 只有 select 没有 insert/update => 写路径缺。

### 第 3 步 · 写规格 JSON

复制 `assets/spec-template.json`。范例 `examples/member-bindcard.json`（会员绑卡，8 列 7 行，端到端全真实）。

要点：

- `chain.rows[]` 是主体：每行按列键 `req|gw|svc|mod|file|method|ds|table` 放一个芯片或芯片数组
- 芯片字段：`cn`（中文业务动作）、`code`（卡片上显示的代码符号）、`sub`（一句话说清为什么有这步）
- 供校验的字段：`file` / `method` / `line` / `table` / `ds`
- 存储列写库名或数据源；表列只写表名 / topic
- `glossary[]` >= 10 条：业务名词 / 代码英文 / 出现位置 / 为什么有这个词
- `gaps[]` 三级：`blocker`（功能其实没实现）/ `warn` / `info`

### 第 4 步 · 三道闸门，全过才出图

```bash
node scripts/verify.mjs <spec.json> <仓库根目录>      # 事实命中率必须 100%
node scripts/render.mjs <spec.json> <out.html> assets/diagram.css
python scripts/check_layout.py <out.html>            # 布局闸门，必须 problems=[]
```

- `verify.mjs`：把每条 文件/方法/表名 拿回仓库核对，未命中逐条列原因，退出码非 0（自动跳过 proto/gap）。支持 .java/.ts/.js/.py/.go/.cs/.php/.rb/.kt/.xml/.sql
- `check_layout.py`：无头浏览器实测四类问题 —— **卡片溢出**、**连线穿卡**、**连线贴卡边**（<6px）、**色带与列头错位**（>1px）

**布局闸门不是可选步骤**。文字挤、泳道错位、线贴边，这个脚本一次就能抓出来。

### 第 5 步 · 交付

产物写到**项目仓库外**，文件名 `<域>-数据链路.html`。**只交 HTML，不导 PNG**；自检截图放临时目录，看完即删。

汇报格式：结论（几条链路、真实/原型/缺口各几条）/ 产物路径 / 缺口清单 / 下一步。

## 换一个新项目 / 新功能怎么做

**换项目**：重跑第 0 步判断栈 → 读 `references/stack-recipes.md` 对应配方 → 第 1 步起照做。CSS 和渲染器完全不动。

**换功能（同项目）**：只换规格 JSON。已画过的域把规格留在 `examples/` 当基线，新图先读最接近的一份，抄它的链路切分粒度。

## 参考文件

- `references/stack-recipes.md` —— 各语言/框架的检索配方（**先读这个**）
- `references/project-profile.example.md` —— 「项目画像」范例：怎么把一个项目的分层、路由机制、表命名口径写成一份速查

遇到新项目，建议先写一份 `project-profile.md` 放在项目侧（不要放进技能目录），把该项目的分层惯例、命名口径、常见坑记下来，下次画图直接读。

## 硬约束

- 只读仓库，不修改任何源文件
- 不执行任何 git 命令
- 产物一律写在仓库外
- 图上每条事实都能回答「你在哪个文件哪一行看到的」
- 不输出凭据、密钥、连接串内容
