# business-scenario-design · 业务梳理/功能设计强制场景推演

让 AI 在做「业务梳理 / 功能设计」时**不许简化、不许只写顺利路径、不许用「用户」泛指角色**。

## 解决什么问题

AI 做需求分析有一个稳定的失败模式：走最短可交付路径，一段概述 + 一个方案交差，角色写成「用户」，异常场景写「提示错误信息」，结尾用「后续可扩展」收口。

不是知识不足，是**没有东西强制它产出具体内容**。这个技能就是那道门禁。

## 触发条件

用户消息中出现「**业务梳理**」或「**功能设计**」时自动生效。任务看起来很小、很急、很明确也不例外。

## 六步强制产物（缺一项即未完成）

1. **角色卡** — 身份 / 权限边界 / 使用频次 / 熟练度 / 使用时的真实状态 / 真正想完成的事，六格填满；必须含至少一个非操作者角色（审批人、被通知人、事后查账的人）
2. **场景流水** — 每个角色 ≥3 条，六段式：触发 → 前置条件 → 操作序列 → 系统反馈 → 异常分支 → 结束状态；必须覆盖顺利路径、新手首次、出错/断网/并发
3. **状态与数据推演** — 改动哪些字段、谁有权限改、改完别人看到什么、撤销怎么办、历史留痕
4. **边界清单** — 空数据 / 超量 / 重复提交 / 多人并发 / 权限不足 / 跨角色交接 / 超时失效 / 格式异常
5. **反简化自检七问**
6. **Gherkin 验收标准** — 角色必须具名

外加第七项：**待确认问题**。拿不准的列出来问，不许自己假设一个简化版本糊过去。

## 禁用词

「用户」（泛指）、等等、后续可扩展、简单处理即可、一般来说、基本可以、视情况而定、类似地。

## 安装

把整个目录放进目标平台的技能目录，刷新会话即生效：

| 平台 | 技能目录 |
|---|---|
| 当前环境（DSH） | `$DSH_HOME/skills/` 或 `~/.agents/skills/` |
| Claude Code | `~/.claude/skills/` |

## 与其它技能配合

- 外层骨架用 `brainstorming`：先设计、后动手，未获批准不写实现代码
- 需要正式文档时叠加 `prd-development`
- 需要流程图/状态机时用 `archify`
- 需要拆迭代时用 `user-story-mapping-workshop`

## 验证样本

用 `dsh-cost-advisor` 的「月度省钱账本」功能跑通：4 个具名角色（含 1 个非操作者）、11 条场景、8 项边界、4 条 Gherkin。抓到两个真实缺口——跨月零点缓存导致显示 ¥0.00、成员离职后团队总额骤降。
